# works-core — мини-СДО для учебной практики

Раздача материалов, приём отчётов, бригады, сценарии ОПС, проектор.
Чистый **Python 3.10+** — только стандартная библиотека, без зависимостей.

## Быстрый старт

- `START.bat` — запуск (порт аргументом: `START.bat 8081`); `DEMO.bat` — с демо-данными. Оба стартуют и симулятор velxio (бэкенд `:8001` + фронтенд `:5173`) — уже работающие части не перезапускаются, а при остановке СДО по Ctrl+C останавливается поднятый им симулятор.
- Симулятор вручную: флаг `--sim` (`python server.py --port 8080 --sim`, путь можно указать: `--sim E:\AI\velxio`, по умолчанию — соседний каталог; без `--sim` сервер работает как раньше). Отдельно velxio: `E:\AI\velxio\start-velxio.bat`.
- Вручную без симулятора: `python server.py --port 8080 --store данные --demo`
- Пароль преподавателя: `--pass СЕКРЕТ` (сохраняется, смена — в панели) или `--no-pass` (только в защищённой сети). Без флагов — генерируется и печатается в консоли.

## Возможности

- **Курсы → занятия → задания.** Конструктор форм отчёта (текст, число, выбор, чекбоксы, файлы — см. `templates/README.md`), описание в Markdown, срок сдачи с пометкой «просрочено».
- **Сдачи с версиями.** Файлы — на диске (`данные/сдачи/…`), история версий, вердикты с баллами, автопроверка модулями (событие `grade`).
- **Панель преподавателя:** курсы, занятия, задания, студенты, сдачи, CSV-журнал, смена пароля (PBKDF2).
- **Импорт группы:** txt-файл `ФИО;Группа;Бригада` (или вставка списка; UTF-8/cp1251; `#` — комментарии; дубликаты пропускаются). Карточка импорта — прямо на главной панели.
- **Пакет курса:** «📦 Скачать курс» на странице курса выгружает .zip (занятия, задания, раздатка с планами, сдачи с результатами); «📦 Импорт курса» на панели разворачивает пакет с ремапом id и слиянием студентов по ФИО — курс переносится на другой компьютер или к другому преподавателю. Кнопки — отдельный модуль `coursepkg`.
- **Промты для ИИ:** `docs/ПРОМТ-МОДУЛЬ.md` (нейросеть пишет модули works-core) и `docs/ПРОМТ-КУРС.md` (нейросеть составляет курсы в формате пакета).
- **Доступ:** курсы открываются группам («🏫 Доступ группам»); задания и занятия — бригадам («📤 Выдача бригадам»). Невыданное студентам не показывается: скрыты задания, занятия без доступных заданий, а на странице курса в списке студентов видны только зачисленные (полный список — в «Зачисление»; зачислять можно по одному, целой группой или всех; списки свёрнуты по умолчанию).
- **Бригады:** студенты регистрируют сами (название, вступление, выход), максимальный состав назначает преподаватель; бригада сдаёт **один отчёт на всех** (participants). Преподаватель может **включить или отключить бригаду** («👷 Бригады» на странице курса): отключённая не принимает сдачи за бригаду и недоступна для вступления, состав сохраняется. Бригады можно **отключить для всего курса** — тогда студенты сдают лично, регистрация бригад на странице курса скрыта, а выдача бригадам недоступна.
- **Симулятор Arduino (velxio):** модуль «sim» встраивает open-source эмулятор плат (velxio.dev) прямо в страницу задания — студент собирает схему, пишет и компилирует скетч не выходя из СДО. Кнопка «↗ Открыть симулятор» открывает его в новой вкладке, кнопка «📥 Импортировать схему в отчёт» забирает текущий проект из симулятора (postMessage-мост, патч velxio описан в velxio/LOCAL_CHANGES.md) и прикрепляет файлом схемы к первому файловому полю формы отчёта. URL симулятора привязывается к заданию в панели; адрес берётся с хоста, на котором открыт СДО (порт — в modules/sim/модуль.json, ключ «порт»), либо задаётся явно ключом «url». Проект в симуляторе не теряется: черновик работы автосохраняется (каждые 3 с и при закрытии вкладки) и восстанавливается при возврате к заданию.
- **Массовая выдача:** матрица «задания × бригады» на странице занятия — расставить галочки и сохранить всё разом.
- **Очередь проверки:** карточка «⚠️ Требуют проверки: N» на главной панели — все непроверенные сдачи (последняя версия без вердикта) со ссылками прямо на проверку; исчезают по мере вердиктов.
- **Резервная копия** (модуль `backup`): при каждом запуске сервера архив всего хранилища сохраняется в `данные/бэкап/` (хранятся последние 3); кнопка на панели скачивает такой же архив (.zip) в один клик.
- **Мои задания** (модуль `mytasks`): личная страница студента `/my` — все видимые задания по всем курсам со статусами (не сдано / на проверке / принято / доработка), баллами и сроками; ссылка появляется в шапке. Отчёт бригады показывается всем её участникам.
- **Все работы архивом** (модуль `workszip`): кнопка «📥 Все работы (.zip)» на странице задания и страница `/staff/works` — по папке на студента/бригаду, файлы всех версий и «отчёт.txt» с ответами и вердиктом.
- **Шаблоны заданий** (модуль `tasktpl`): кнопка «🗃 В шаблоны» на странице задания сохраняет заготовку (название, описание, форма, срок, критерии); на `/staff/tpl` задание из шаблона создаётся в любом занятии одним кликом.
- **Режим отладки** (модуль `debug`): страница `/debug` — прямой доступ к реестру: правка/добавление/удаление любой записи (JSON), реестр целиком, перечитывание с диска, правка данных модулей. Все действия — в журнале аудита; изменения не проверяются на корректность структуры.
- **Офлайн-сдача** (модуль `offline`): на странице задания — «⬇️ Бланк» (автономный HTML с ФИО студента и индивидуальным токеном); студент работает дома и загружает файл работы на «📥 Офлайн-сдача». Кнопка «⬇️ Бланки» в шапке — страница со **всеми доступными заданиями разом**: скачать выбранные или все бланки одним .zip (по папке на занятие). Преподаватель: `/staff/offline` — пачечный импорт работ **drag-and-drop** (несколько файлов или целая папка разом), токены выдачи, детект возможного списывания (сходство текстов и файлов).
- **Сценарии УП** (модуль `scenarios`): импорт комплектов из папки «Сценарии для УП» → занятие с материалами (раздатка 02, планы 05, обозначения 06) и заданием на каждую карточку сценария. Эталоны (`etalon`, `dev`, `notes`) и план преподавателя студентам не утекают. Кнопка «Обновить» чинит ранее импортированные занятия.
- **Интерактивный план:** студент расставляет обозначения из `legend` по плану сооружения (клик — поставить, клик по устройству — убрать, счётчики, автосохранение), размещение уходит вместе с отчётом; преподаватель видит план сдачи в режиме read-only.
- **Антиплагиат и нейро-контроль** (модуль `plag`): при каждой сдаче, **до вердикта**, текст ответов сравнивается со всеми уже сданными работами того же задания (шинглы слов + Жаккар; показываются совпавшие фрагменты; одинаковые файлы — 100%). Эвристическая нейро-оценка текста: штампы-клише, однообразие предложений, бедность словаря — работает офлайн и честно помечена «не доказательство». Результаты — карточкой на странице сдачи и сводкой на `/plag`; при сходстве ≥60% или нейро ≥60% сдача получает флаг.

- **Баг-репорты** (модуль `bugrep`): студент нажимает плавающую кнопку «🐞 Баг», описывает проблему и может приложить скриншот — репорт уходит на сервер вместе со страницей, браузером, ФИО/группой и IP (работает и для неавторизованных — с пометкой «не залогинен»). Преподаватель видит плашку «🐞 Баг-репорты (N новых)», ведёт разбор со статусами (новый → в работе → решён/отклонён) и удаляет закрытые.
- **Тёмная тема** — тумблер 🌙 в шапке (запоминается), **проектор «🏆 ТАБЛИЦА ЛИДЕРОВ»** (`/board`): подиум топ-3, медали, живые часы, прогресс-бары, рейтинг бригад и студентов.

## Модули (`modules/`)

| Модуль | Назначение |
|---|---|
| `staff` | Панель преподавателя |
| `board` | Проектор-табло |
| `export` | CSV-журнал (`/staff/export/course/<id>`) |
| `classic_theme` | Палитры оформления по курсам |
| `scenarios` | Импорт и выдача сценариев УП |
| `coursepkg` | Пакет курса: экспорт/импорт (.zip) |
| `backup` | Резервная копия: автокопия при старте сервера + скачивание (.zip) |
| `workszip` | Все работы по заданию одним архивом (.zip) |
| `tasktpl` | Шаблоны заданий: «В шаблоны» на задании → создание из шаблона |
| `mytasks` | «Мои задания» — личная страница студента (/my) |
| `debug` | Режим отладки: правка любого параметра реестра (JSON), данные модулей |
| `offline` | Офлайн-сдача: бланк задания (.html с токеном) → работа дома → загрузка файла работы; пачечный импорт, детект списывания |
| `plag` | Антиплагиат и нейро-контроль: сходство со сданными работами + эвристика «нейросетевого» текста |
| `sim` | Симулятор Arduino (velxio) в странице задания: схема и скетч, импорт схемы в отчёт, автосохранение черновика |
| `bugrep` | Баг-репорты: кнопка «🐞 Баг» у студента, панель разбора со статусами у преподавателя |

Модуль = `модуль.json` (манифест, `api: 1`) + `модуль.py` с `register(ctx)`. Включение/порядок — на `/_modules`.

## CI: испытательный полигон и правки без остановки занятия (`ci.py`)

Конвейер: **правка -> компиляция -> стенд (:8090) -> проверки -> боевой (:8080)**.
Стенд - второй сервер СДО со своей копией данных (хранилище `_stage_store`),
его растит и останавливает сам `ci.py`: там нет студентов, поэтому
ядро на стенде перезапускается смело.

**Наблюдатель живёт вместе с сервером:** СДО при старте само запускает `ci.py watch` (для боевого хранилища - автоматически; `--no-ci-watch` отключает, `--ci-watch` принуждает) и гаснет вместе с ним: если сервер недоступен, наблюдатель сам завершается. Отдельно наблюдателя можно запустить `python ci.py watch` - он также завершится, если сервер выключен.

- **правки модулей** (`modules/<id>/модуль.py`, `модуль.json`): горячая
  перезагрузка на стенде -> проверки -> та же перезагрузка на боевом
  (студенты ничего не замечают). Битый файл не валит модуль - ни на
  стенде, ни на боевом.
- **правки ядра** (`core/*`, `server.py`): полный перезапуск СТЕНДА,
  проверки; на боевой новый код попадает только командой
  `python ci.py promote` - её запускает человек, это и есть согласие
  на перезапуск боевого (входы студентов не слетают: ключ сессий в
  хранилище). Если стенд красный - на боевой ничего не уходит.
- если боевой был выключен в момент правки, наблюдатель запомнит
  модули и догрузит их, как только боевой появится.

```bat
python ci.py check            & rem однократная проверка: компиляция + пробный старт (:8097)
python ci.py check --full     & rem полный смоук (tests/_test2.ps1)
python ci.py stage            & rem поднять/проверить стенд (:8090, копия боевых данных при --fresh)
python ci.py stage --fresh    & rem стенд на свежей копии боевого хранилища
python ci.py watch            & rem конвейер: стенд -> проверки -> боевой
python ci.py deploy module=sim   & rem перезагрузить модуль на БОЕВОМ вручную
python ci.py promote          & rem перезапустить БОЕВОЙ на проверенном ядре (спросит подтверждение)
python ci.py promote --yes    & rem то же без вопроса
```

Параметры: `--url http://localhost:8080` (боевой), `--interval 2`,
`--token XXX` (иначе `данные/_ci.token`; у стенда свой токен,
`_stage_store/_ci.token`). Журнал: `_ci.log`. Стенд смотрит те же файлы
модулей, что и боевой: на стенде проверяется ровно тот код, что на диске.

Механика `/_reload`: только localhost + токен. Безопасный порядок
обновления: новый код импортируется до снятия старого -> синтаксическая
ошибка оставляет старую версию работать; сбой при `register()` откатывает
прежний код.

## Данные и структура

- Реестр: `данные/реестр.json` (атомарная запись; повреждённый сохраняется как `реестр.json.битый-*`).
- Файлы: `данные/сдачи/<задание>__<студент>/v<N>/`, материалы: `данные/раздатка/<курс>/<занятие>/`.
- Секреты: `данные/_секрет.key` (HMAC-cookie), `данные/_пароль.hash` (PBKDF2 60000), `данные/_modules_state.json`, `данные/_ci.token` (токен CI для POST /_reload).

## Безопасность

HMAC-подписанные cookie студентов, PBKDF2-пароль с солью, лимит попыток входа персонала (5/10 мин на IP), сессии с TTL, ThreadingHTTPServer, проверка путей (commonpath), без утечки текста исключений.
