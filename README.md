# Works-CORE

**Ядро для сбора и раздачи учебных работ.** Три функции: раздать материал → назначить задание → собрать отчёт. Всё остальное — модули.

## Запуск

Требуется Python 3.10+ (только stdlib — работает и на 3.13/3.14).

```bash
:: демо-режим (без пароля)
python server.py --port 8080 --demo --no-pass

:: с паролем
python server.py --port 8080 --pass МОЙПАРОЛЬ

:: без пароля (только в защищённой сети)
python server.py --port 8080 --no-pass
```

Пароль можно сменить в панели (`/staff` → «Сменить пароль»); он хранится как
PBKDF2-хеш и переживает перезапуск. При запуске без `--pass` используется
сохранённый пароль, а если его нет — генерируется новый.

## Импорт группы

Панель → страница курса → «Импорт группы (txt)»: загрузите файл или вставьте
список. Формат — один студент в строке: `ФИО`, `ФИО;Группа` или `ФИО, Группа`
(кодировка UTF-8 или Windows-1251, строки с `#` — комментарии, дубликаты
пропускаются).

Откройте в браузере:
- `http://localhost:8080/` — студенту
- `http://localhost:8080/staff` — преподавателю
- `http://localhost:8080/_modules` — состояние модулей

## Ядро (core)

Ядро умеет ровно три вещи:

| Функция | Что делает |
|---|---|
| `core.distribute(course_id, lesson_id)` | Возвращает список материалов занятия |
| `core.assign(task_id)` | Возвращает задание с формой отчёта |
| `core.collect(task_id, student_id, answers, files)` | Сохраняет сдачу работы |

HTTP-сервер и аутентификация встроены в ядро, чтобы оно было самодостаточным.
Всё остальное (панель, вердикты, состав группы, доска, выгрузки) — модули.

Загруженные студентами файлы сохраняются на диск в
`данные/сдачи/<задание>__<студент>/v<N>/`; преподаватель скачивает их со
страницы сдачи.

После сохранения сдачи ядро вызывает событие `grade` — модули с правилами
(например, `verdict`) могут выставить вердикт автоматически.

## Модули

Модуль = папка с `модуль.json` (манифест) и опционально `модуль.py` (код).

```json
{
  "id": "staff",
  "name": "Панель преподавателя",
  "version": "1.0.0",
  "api": 1,
  "kind": "python",
  "enabled": true
}
```

Модуль получает `ctx` (ModuleContext) с методами:
- `add_route(method, path, handler, access)` — добавить маршрут
- `on(event, handler)` — подписаться на событие
- `list_courses()`, `list_students()`, `get_task(id)` — чтение данных
- `add_course(title)`, `add_student(fio, group)` — создание (только от преподавателя)
- `set_verdict(task_id, student_id, verdict, score, comment)` — вынести решение
- `render_page(title, body, staff)` — страница в вёрстке ядра
- `delete_task(id)` — удалить задание вместе со сдачами

События ядра: `page.head` (фрагменты `<head>`), `submit.before` (верните
строку-ошибку, чтобы отклонить сдачу), `submit.after`, `grade` (автопроверка —
верните словарь с `verdict`/`score`/`status`/`comment`), `verdict.after`.

Страница `/modules` показывает состояние всех модулей.

## Формат задания

Задание задаётся JSON-формой. Каждое поле — объект с `тип`, `ключ`, `вопрос`:

```json
{"тип": "number", "ключ": "loops", "вопрос": "Количество шлейфов", "обязательно": true}
```

Встроенные типы полей: `text`, `textarea`, `number`, `select`, `radio`, `checkbox`,
`checkboxes`, `file`, `static`, `date`, `email`, `tel`.

Описание задания — Markdown (заголовки, списки, **жирный**, *курсив*, `код`).
Ядро рендерит его безопасно: HTML во входе экранируется.

Срок сдачи хранится в `настройки.срок` (например, «2026-12-31 18:00»);
сдача после срока помечается как просроченная.

## Формат реестра

Единственный файл `данные/реестр.json`:
- `курсы` — список курсов (у курса может быть список зачисленных `студенты`;
  пустой список = курс открыт всем)
- `занятия` — список занятий (привязаны к курсу)
- `задания` — список заданий (привязаны к занятию)
- `студенты` — список студентов
- `сдачи` — словарь `"task__student": {...}` с версиями и ответами

## Модули: экспорт и доска

- **export** — кнопка «CSV» на странице курса: журнал сдач (UTF-8 BOM, Excel).
- **board** — `/board`: сводка сдач по курсам для экрана-проектора,
  автообновление каждые 30 секунд.
