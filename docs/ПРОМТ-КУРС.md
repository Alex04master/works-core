# ПРОМТ: нейросеть составляет курс для works-core

> Как пользоваться: скопируйте весь файл в чат нейросети и в самом конце,
> после раздела «ЗАДАЧА», опишите курс: дисциплина, группа, число занятий,
> тема практических работ. Нейросеть выдаст файлы пакета; их упаковывают
> в .zip и импортируют кнопкой «📦 Импорт курса» на панели преподавателя.
> Промт универсальный: подходит для любой дисциплины (электромонтаж,
> сети, программирование, химия, делопроизводство — что угодно).

---

## РОЛЬ И ЦЕЛЬ

Ты — опытный методист и преподаватель. Дисциплину и уровень группы
определяет задача пользователя. Ты готовишь **курс** для учебного LMS
«works-core» в формате **пакета курса**: набор JSON-файлов и файлов
раздатки, упакованный в .zip. Пакет импортируется целиком: система сама
перенумерует id и зальёт материалы.

Система: works-core — LMS на чистом Python (без зависимостей), интерфейс
на русском. Студенты сдают отчёты (лично или бригадой — один отчёт на
всех), преподаватель выдаёт задания бригадам и проверяет их с чек-листом
критериев. К каждому заданию можно подключить интерактивный план/схему —
виджет, где студенты расставляют условные обозначения кликами.

## СОСТАВ ПАКЕТА (.zip)

```
пакет.json                    — манифест формата
курс.json                     — курс (название, группы доступа)
занятия.json                  — список занятий
задания.json                  — список заданий
студенты.json                 — (опционально) список студентов
сдачи.json                    — (опционально) результаты
раздатка/<id занятия>/<файлы> — материалы занятий
```

Все JSON — UTF-8, отступы, текст на русском (или языке курса). `id` —
любые уникальные строки (`"c1"`, `"l1"`, `"t1"`, `"s1"`): при импорте
система заменит их своими.

Сборка zip (пример):

```powershell
Compress-Archive -Path курс\* -DestinationPath курс.zip
```
или
```python
import shutil; shutil.make_archive("курс", "zip", "курс")
```
(внутри zip файлы должны лежать с указанных имён, без лишней вложенной
папки — проверь, что `пакет.json` в корне архива).

## пакет.json

```json
{"формат": "works-core-курс", "версия": 1, "выгружен": "2026-11-04T12:00:00"}
```

## курс.json

```json
{
  "id": "c1",
  "title": "Название курса",
  "студенты": [],
  "группы": ["П-21"],
  "бригада_макс": 5
}
```

- `студенты` — id зачисленных (если ведёшь студентов в студенты.json);
  пусто и в `студенты`, и в `группы` = курс открыт всем.
- `группы` — курс увидят только эти учебные группы (плюс зачисленные).
- `бригада_макс` — максимальный состав бригады (0 = умолчание 3).
  Ставь, если отчёты сдаются бригадами; для индивидуальных работ — 0
  или не указывай.

## занятия.json

```json
[
  {"id": "l1", "course": "c1", "title": "Название занятия",
   "материалы": [{"тип": "файл", "имя": "02_Инструкция.html"}]}
]
```

- `материалы` — что студенты видят в блоке «Материалы» занятия; `имя` —
  файл из `раздатка/l1/`. Можно пусто.
- Служебные файлы виджета (`event.js`, `plans.js`) кладутся в раздатку,
  но в `материалы` их НЕ включают — виджет читает их сам.

## задания.json — ГЛАВНОЕ

```json
[
  {"id": "t1", "lesson": "l1", "title": "Задание 1 · Название работы",
   "описание": "## Ситуация\n…",
   "форма": [ …поля… ],
   "настройки": {"план": "СХ-01",
                 "критерии": ["Верно определён состав оборудования — 30 балл.",
                              "…"]},
   "выдано": []}
]
```

### Типы полей формы

| `тип` | Назначение | Параметры |
|---|---|---|
| `static` | заголовок-разделитель | `подсказка` |
| `text` | однострочный текст | `место` (placeholder) |
| `textarea` | многострочный | `строк` (1-20), `место` |
| `number` | число | `мин`, `макс`, `шаг`, `место` |
| `select` | выпадающий список | `варианты`: [строки] |
| `radio` | радиокнопки | `варианты`: [строки] |
| `checkbox` | одна галочка | `подсказка` |
| `checkboxes` | несколько галочек | `варианты`: [строки] |
| `file` | файл (поле drag-and-drop, один) | `accept` |
| `hidden` | скрытое поле (данные виджетов) | — |
| `date` / `email` / `tel` | соответствующие input | `мин`/`макс`/`место` |
| `shlei` | предметная таблица «Ведомость шлейфов» (5 колонок: №, тип, прибор, количество, комментарий) — специализированное поле для дисциплин по сигнализациям | `строк` (по умолч. 10) |
| `firmware` | прикрепление нескольких файлов «прошивки прибора» (drag-and-drop) — специализированное поле для приборных дисциплин | `лимит` (по умолч. 5) |

Общие параметры поля: `ключ` (латиница, уникально в форме), `вопрос`
(подпись на языке курса), `обязательно` (true/false).

**Как выбирать поля для любой дисциплины:** расчёты и обоснования —
`textarea` с `обязательно`; числовые ответы — `number`; выбор варианта —
`select`/`radio`; вложения (схема, фото макета, отчёт) — `file`;
таблицу данных студента, если она нужна, кодируй несколькими полями
`text`/`number` или проси вложить файл. Специализированные `shlei`/
`firmware` используй только если дисциплина про сигнализации/приборы —
для остальных курсов они не нужны.

### Готовая форма практического задания (универсальный шаблон)

```json
"форма": [
  {"ключ": "plan_data", "тип": "hidden",
   "вопрос": "Размещение элементов на плане"},
  {"ключ": "answer", "тип": "textarea", "вопрос": "Решение и обоснование",
   "обязательно": true, "строк": 8,
   "место": "Ход решения, расчёты, выводы…"},
  {"ключ": "attachment", "тип": "file",
   "вопрос": "Вложение (схема, фото, отчёт)"}
]
```
Поле `plan_data` и `hidden` включай ТОЛЬКО если к заданию подключён
интерактивный план (см. ниже). Специализированный вариант для
дисциплин по сигнализациям: добавить `shlei` (loops, строк 10) и
`firmware` (лимит 5) — см. таблицу выше.

### Семантика выдачи

- У задания с `настройки.план` отсутствие ключа `выдано` = задание **ждёт
  выдачи** (студенты его не видят), `"выдано": []` — видно всем,
  `["Бригада-1"]` — только бригаде.
- У обычного задания (без плана) отсутствие ключа = видно всем сразу.
- Практические работы, которые преподаватель раздаёт поэтапно, оставляй
  с `"выдано"`-управлением: просто не добавляй ключ `выдано` для заданий
  с планом, либо ставь `[]`, если задание открыто сразу.

## ОПИСАНИЕ ЗАДАНИЯ (Markdown)

Поддерживается: `#/##/###` заголовки, списки `- ` и `1. `, `**жирный**`,
`*курсив*`, `` `код` ``. Всё остальное экранируется. Рекомендуемая
структура практического задания (адаптируй названия разделов под
дисциплину):

```
### Ситуация
(кто, где, что нужно сделать — постановка задачи)
### Исходные данные
- параметр — значение
### Оборудование / стенды
- A1 — название устройства/реактив/инструмента
### Задания
1. …
2. …
### Что сдаёт студент (бригада)
- расчёт, схема, таблица…
### Критерии оценки
(дублируются списком в настройки.критерии)
### Типовые ошибки
- …
```

`настройки.критерии` — список строк вида `"Текст — 30 балл."`; они же
становятся чек-листом проверки у преподавателя.

## ИНТЕРАКТИВНАЯ СХЕМА/ПЛАН (опционально, для любой дисциплины)

К заданию можно подключить виджет: студенты выбирают условное
обозначение и кликами расставляют его на плане/схеме (здание, разводка
сети, компоновка лабораторного стенда, разрез установки — что угодно).
В раздатку занятия кладутся два файла:

`event.js`:
```js
window.EVENT = {
  title: "Название работы",
  place: "объект",
  stands: {"A1": {"code": "A1", "name": "Название оборудования"}},
  legend: [
    {"key": "node", "label": "Рабочее место (4)",
     "rule": "не ближе 1 м к проходу",
     "color": "#b91c1c", "fill": "#fff", "shape": "circle", "text": "Р"}
  ]
};
```
- `legend.key` — латиница (уходит в данные план_data);
  `shape`: `circle` | `square` | `rect`; `text` — подпись на элементе;
  `rule` — правило размещения (показывается студенту в подсказке).

`plans.js` (эталоны НЕ включаются — `dev` и `notes` всегда пустые):
```js
window.PLANS = [
  {"id": "СХ-01",
   "rooms": [
     {"x": 0, "y": 0, "w": 6, "h": 4, "n": "Помещение 1", "d": "подпись"},
     {"x": 6, "y": 0, "w": 4, "h": 4, "n": "Коридор"}
   ],
   "dev": [], "notes": []}
];
```
- Координаты — в единицах комнат (метры или шаги сетки); `n` — название,
  `d` — подпись. «Комнатами» могут быть любые зоны: помещения, секторы,
  блоки установки, сегменты сети.
- В задании: `"настройки": {"план": "СХ-01"}` + поле `hidden plan_data`.

## СЦЕНАРНЫЙ КОМПЛЕКТ (отдельный путь импорта, опционально)

Курс можно собрать и через модуль «Сценарии УП»: папка-комплект с файлами
`01…07*.html` (страницы сценария), `event.js`, `cards.js`, `plans.js`.
`cards.js`:

```js
window.CARDS = [
  {"id": "СЦ-01", "title": "…", "lvl": "базовый", "time": "15 мин",
   "team": "бригада 3 чел.", "role": "роль студента",
   "story": "ситуация", "obj": "объект",
   "data_table": [["Параметр", "Значение"]],
   "tasks": ["шаг 1", "шаг 2"], "given": ["что сдаёт"],
   "criteria": [["Критерий", "30"]],
   "traps": ["типовая ошибка"], "stands": ["A1"]}
];
```
Пакет курса и сценарный комплект не смешивают: пакет — для целого курса,
комплект — для импорта занятий-сценариев в существующий курс.

## МЕТОДИЧЕСКИЕ ПРАВИЛА

- 2–5 заданий на занятие; форма короче — лучше; решения и расчёты —
  через `textarea` с `обязательно`.
- Каждый значимый шаг работы проверяем критерием; критерии в порядке
  убывания веса; суммарный вес ≈ 100.
- Данные для решения (таблицы, характеристики, нормативы) — в описании
  или в html-файлах раздатки, а не в вопросах формы.
- Не включай эталоны, ответы и решения в раздатку: студенты видят эти
  файлы.
- Предметная терминология — на языке дисциплины; служебные поля формы
  (`ключ`) — латиница.
