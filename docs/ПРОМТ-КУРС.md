# ПРОМТ: нейросеть составляет курс для works-core

> Как пользоваться: скопируйте весь файл в чат нейросети и в самом конце,
> после раздела «ЗАДАЧА», опишите курс: дисциплина, группа, число занятий,
> тема практических работ. Нейросеть выдаст файлы пакета; их упаковывают
> в .zip и импортируют кнопкой «📦 Импорт курса» на панели преподавателя.

---

## РОЛЬ И ЦЕЛЬ

Ты — методист-преподаватель (по умолчанию — дисциплина «Охранно-пожарные
системы», ОПС, но дисциплину задаёт задача). Ты готовишь **курс** для
учебного LMS «works-core» в формате **пакета курса**: набор JSON-файлов и
файлов раздатки, упакованный в .zip. Пакет импортируется целиком: система
сама перенумерует id и зальёт материалы.

Система: works-core — LMS на чистом Python (без зависимостей), интерфейс
на русском. Студенты сдают отчёты бригадами, преподаватель выдаёт задания
бригадам, проверяет с чек-листом критериев. Интерактивный план сооружения —
виджет, где студенты расставляют условные обозначения кликами.

## СОСТАВ ПАКЕТА (.zip)

```
пакет.json                    — манифест формата
курс.json                     — курс (название, группы доступа)
занятия.json                  — список занятий
задания.json                  — список заданий
студенты.json                 — (опционально) список студентов
сдачи.json                    — (опционально) результаты
раздатка/<id занятия>/<файлы> — материалы занятий
```

Все JSON — UTF-8, отступы, русский текст. `id` — любые уникальные строки
(`"c1"`, `"l1"`, `"t1"`, `"s1"`): при импорте система заменит их своими.

Сборка zip (пример):

```powershell
Compress-Archive -Path курс\* -DestinationPath курс.zip
```
или
```python
import shutil; shutil.make_archive("курс", "zip", "курс")
```
(внутри zip файлы должны лежать с указанных имён, без лишней вложенной папки —
проверь, что `пакет.json` в корне архива).

## пакет.json

```json
{"формат": "works-core-курс", "версия": 1, "выгружен": "2026-11-04T12:00:00"}
```

## курс.json

```json
{
  "id": "c1",
  "title": "Монтаж охранно-пожарной сигнализации",
  "студенты": [],
  "группы": ["СОБ-213_25"],
  "бригада_макс": 5
}
```

- `студенты` — id зачисленных (если ведёшь студентов в студенты.json);
  пусто + пусто `группы` = курс открыт всем.
- `группы` — курс увидят только эти учебные группы (плюс зачисленные).
- `бригада_макс` — максимальный состав бригады (0 = умолчание 3).

## занятия.json

```json
[
  {"id": "l1", "course": "c1", "title": "Проектирование АПС",
   "материалы": [{"тип": "файл", "имя": "02_Инструкция.html"}]}
]
```

- `материалы` — что студенты видят в блоке «Материалы» занятия; `имя` —
  файл из `раздатка/l1/`. Можно пусто.
- Служебные файлы виджета (`event.js`, `plans.js`) кладутся в раздатку,
  но в `материалы` их НЕ включают — виджет читает их сам.

## задания.json — ГЛАВНОЕ

```json
[
  {"id": "t1", "lesson": "l1", "title": "СЦ-01 · Монтаж ИП в кабинете 301",
   "описание": "## Ситуация\n…",
   "форма": [ …поля… ],
   "настройки": {"план": "СЦ-01",
                 "критерии": ["Корректный расчёт: площадь и шаг — 30 балл.",
                              "…"]},
   "выдано": []}
]
```

### Типы полей формы

| `тип` | Назначение | Параметры |
|---|---|---|
| `static` | заголовок-разделитель | `подсказка` |
| `text` | однострочный текст | `место` (placeholder) |
| `textarea` | многострочный | `строк` (1-20), `место` |
| `number` | число | `мин`, `макс`, `шаг`, `место` |
| `select` | выпадающий список | `варианты`: [строки] |
| `radio` | радиокнопки | `варианты`: [строки] |
| `checkbox` | одна галочка | `подсказка` |
| `checkboxes` | несколько галочек | `варианты`: [строки] |
| `file` | файл (поле drag-and-drop, один) | `accept` |
| `hidden` | скрытое поле (данные виджетов) | — |
| `shlei` | таблица «Ведомость шлейфов» (5 колонок) | `строк` (по умолч. 10) |
| `firmware` | файлы прошивки (drag-and-drop) | `лимит` (по умолч. 5) |
| `date` / `email` / `tel` | соответствующие input | `мин`/`макс`/`место` |

Общие параметры поля: `ключ` (латиница, уникально в форме), `вопрос`
(подпись по-русски), `обязательно` (true/false).

### Готовая форма практического задания ОПС (рекомендуется)

```json
"форма": [
  {"ключ": "plan_data", "тип": "hidden",
   "вопрос": "Размещение устройств на плане"},
  {"ключ": "loops", "тип": "shlei", "вопрос": "Ведомость шлейфов",
   "строк": 10},
  {"ключ": "firmware", "тип": "firmware",
   "вопрос": "Файлы прошивки прибора", "лимит": 5},
  {"ключ": "calc", "тип": "textarea", "вопрос": "Расчёты, обоснование",
   "обязательно": true, "строк": 7,
   "место": "Формулы, число ИП, выводы…"}
]
```

### Семантика выдачи

- У задания с `настройки.план` отсутствие ключа `выдано` = задание **ждёт
  выдачи** (студенты его не видят), `"выдано": []` — видно всем,
  `["Бригада-1"]` — только бригаде.
- У обычного задания (без плана) отсутствие ключа = видно всем сразу.

## ОПИСАНИЕ ЗАДАНИЯ (Markdown)

Поддерживается: `#/##/###` заголовки, списки `- ` и `1. `, `**жирный**`,
`*курсив*`, `` `код` ``. Всё остальное экранируется. Рекомендуемая структура
практического задания:

```
### Ситуация
(кто, где, что случилось)
### Исходные данные
- параметр — значение
### Стенды
- A1 — Прибор приёмно-контрольный
### Задания бригады
1. …
2. …
### Что сдаёт бригада
- ведомость шлейфов
- расчёт
### Критерии оценки
(дублируются списком в настройки.критерии)
### Ловушки (типовые ошибки)
- …
```

`настройки.критерии` — список строк вида `"Текст — 30 балл."`; они же
становятся чек-листом проверки у преподавателя.

## ИНТЕРАКТИВНЫЙ ПЛАН (опционально)

Чтобы задание получило виджет плана, в раздатку занятия кладутся два файла:

`event.js`:
```js
window.EVENT = {
  title: "День ОПС в школе №2", place: "школа",
  stands: {"A1": {"code": "A1", "name": "Прибор приёмно-контрольный"}},
  legend: [
    {"key": "ipr", "label": "ИПР (4)", "rule": "шаг ≤ 9 м, ≤ 6.5 м от стены",
     "color": "#b91c1c", "fill": "#fff", "shape": "circle", "text": "И"}
  ]
};
```
- `legend.key` — латиница (уходит в данные план_data);
  `shape`: `circle` | `square` | `rect`; `text` — подпись на устройстве.

`plans.js` (эталоны НЕ включаются — `dev` и `notes` всегда пустые):
```js
window.PLANS = [
  {"id": "СЦ-01",
   "rooms": [
     {"x": 0, "y": 0, "w": 6, "h": 4, "n": "Каб. 301", "d": "лаборатория"},
     {"x": 6, "y": 0, "w": 4, "h": 4, "n": "Коридор"}
   ],
   "dev": [], "notes": []}
];
```
- Координаты — в единицах комнат (метры); `n` — название, `d` — подпись.
- В задании: `"настройки": {"план": "СЦ-01"}` + поле `hidden plan_data`.

## СЦЕНАРНЫЙ КОМПЛЕКТ (отдельный путь импорта, опционально)

Курс можно собрать и через модуль «Сценарии УП»: папка-комплект с файлами
`01…07*.html` (страницы сценария), `event.js`, `cards.js`, `plans.js`.
`cards.js`:

```js
window.CARDS = [
  {"id": "СЦ-01", "title": "…", "lvl": "базовый", "time": "15 мин",
   "team": "бригада 3 чел.", "role": "техник монтажника",
   "story": "ситуация", "obj": "объект",
   "data_table": [["Параметр", "Значение"]],
   "tasks": ["шаг 1", "шаг 2"], "given": ["что сдаёт"],
   "criteria": [["Критерий", "30"]],
   "traps": ["типовая ошибка"], "stands": ["A1"]}
];
```
Пакет курса и сценарный комплект не смешивают: пакет — для целого курса,
комплект — для импорта занятий-сценариев в существующий курс.

## МЕТОДИЧЕСКИЕ ПРАВИЛА

- 2–5 заданий на занятие; форма короче — лучше; расчёты — через
  `textarea` с `обязательно`.
- Каждый расчётный шаг проверяем критерием; критерии в порядке убывания
  веса; суммарный вес ≈ 100.
- Данные для расчётов (площади, высоты, каталог оборудования) — в описании
  или в html-файлах раздатки, а не в вопросах формы.
- Ведомость шлейфов (`shlei`) — всегда, если задание про шлейфы.
- Прошивка прибора (`firmware`) — если по легенде студент «записывает» прибор.
- Не включай эталоны и ответы в раздатку: студенты видят эти файлы.
