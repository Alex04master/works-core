# План: модуль «Подсказки» — локальная нейросеть с RAG по документации стендов

Сохранено 12.11.2026. Идея: студенты спрашивают внешние нейросети про стенды —
получают бред, потому что у той нет ни документации, ни понимания стенда.
Решение: поднять **локальную** LLM на этом же ПК, дать ей векторный индекс
документов (RAG) и встроить подсказки прямо в СДО.

## 1. Железо и что из этого следует

| Компонент | Что стоит | Вывод |
|---|---|---|
| CPU | i7-8700K (6/12 ядер, AVX2) | рабочая лошадка для инференса |
| RAM | 32 ГБ DDR4-2133 | хватает на 2 модели разом (LLM + эмбеддер) |
| GPU | GTX 1050, **2 ГБ VRAM** | для генерации бесполезна — не используем |
| Диск | E: свободно ~690 ГБ | модели держим на E: |
| Python | 3.14.7 | в рантайме СДО — только стандартная библиотека |

Скорость на CPU (замерено на этапе 0, реальный RAG-промпт ~750 ток):
- qwen3:1.7b (по умолчанию): генерация 16,6 ток/с → подсказка ~10–15 с
  целиком (поиск + промпт + ответ до 220 ток).
- qwen3:4b-instruct (глубокий режим): 6,4 ток/с → ~30 с.
- Эмбеддинг bge-m3: < 1 с на запрос, ~0,34 с/текст при батч-индексации.
- Холодная загрузка модели: ~15–20 с (смягчается KEEP_ALIVE=30m — модели
  постоянно висят в памяти, LLM и эмбеддер разом).

## 2. Архитектура

- **Движок — Ollama** (Windows-сервис, не трогает СДО, чистый HTTP API).
  Альтернатива — голый llama.cpp (`llama-server.exe`): то же самое, но
  двумя процессами и руками. Ollama проще в обслуживании.
- **Генерация:** qwen3:1.7b с `think:false` — по умолчанию (замерено:
  16,6 ток/с на CPU, подсказка ~10–13 с; отказывается выдумывать, называет
  источник). «Глубокий» режим — MoE qwen3:30b-a3b-instruct-2507-q4_K_M
  (качество уровня 30B при скорости 3B, ~13–17 с, ~19 ГБ RAM — влезает в
  32 ГБ). «Мгновенный» профиль — qwen3:0.6b (2–5 с). qwen2.5:3b-instruct
  и gemma3:1b — отклонены по качеству ответов.
- **Эмбеддинги:** bge-m3 (многоязычная, хорошо ищет по русским документам).
- **Индекс** — JSON внутри данных модуля (`данные/модули/podskazki/индекс.json`):
  чанки (текст + вектор + источник). Поиск — косинусная близость на чистом
  Python: при ~2–5 тыс. чанков это доли секунды. Никаких pip-зависимостей
  в рантайме СДО.
- **Модуль `podskazki`** в works-core — по образцу `bugrep`: плавающая кнопка
  у студента через событие `page.head`, панель преподавателя, хранение в
  `kv_load/kv_save`. Обновляется через CI без перезапуска сервера.
- Ollama слушает только 127.0.0.1:11434, наружу не светится.

```
Студент (страница задания)
   │  кнопка «🤖 Подсказка» + вопрос (+ контекст задания)
   ▼
модуль podskazki (works-core, stdlib)
   │  лимит → кэш FAQ → RAG-поиск top-4 чанков
   ▼
промт: правила + фрагменты документов + вопрос
   ▼ HTTP (urllib, localhost)
Ollama: bge-m3 (эмбеддинги) + Qwen3-4B Q4 (генерация)
   │
   ▼
ответ с указанием источников → студент; лог вопроса → преподаватель
```

## 3. Что индексируем и что — НЕТ

**Индексируем (видимое студентам):**
- раздатка курсов (`данные/раздатка/...`);
- документы стендов: паспорта, руководства, методички (папка источников);
- описания заданий (title/описание);
- студенческие материалы комплектов УП: раздатка 02, планы 05, обозначения 06.

**Категорически НЕ индексируем:** `etalon`, `dev`, `notes` из сценариев,
план преподавателя, вердикты и сдачи других студентов, служебные данные.
Модуль сценариев их прячет от студентов — модуль подсказок обязан
наследовать это правило.

## 5. Риски и меры

| Риск | Мера |
|---|---|
| Ответ медленный (20–40 с) | кэш FAQ, короткие ответы, при необходимости модель 3B/2B |
| Галлюцинации | жёсткий промт «только по фрагментам», показ источников, «не знаю» — нормальный ответ |
| Утечка эталонов | белый список источников; эталоны никогда не попадают в индекс |
| Очередь студентов | OLLAMA_NUM_PARALLEL=1, лимит на студента, очередь в модуле |
| Ollama упала/обновилась | карточка статуса, вежливая деградация («подсказки временно недоступны») |
| Модель «умнеет» не по делу | ответы логируются — преподаватель видит бред и правит промт/индекс |

## 7. Вариант: внешние API-агрегаторы (исследовано 12.11.2026)

Архитектура модуля это допускает: клиент делает OpenAI-совместимым
(покрывает и Ollama `/v1`, и большинство агрегаторов), провайдер задаётся
настройкой (base_url + ключ + модель). Эмбеддинги всегда локальные
(bge-m3) — на индексацию документы наружу не уходят, наружу уходит только
вопрос + топ-фрагменты. Фолбэк: внешний API → при 429/сбой сети →
локальная Ollama; «режим экзамена» — только локально.

Международные бесплатные тарифы из РФ недоступны (проверено по обзору
Хабра от 21.10.2026 и свежим сводам): OpenRouter заблокировал РФ
27.06.2026, Groq — 403 на RU-IP, Gemini — прямой доступ закрыт, VseGPT —
сервис недоступен. Без VPN они не вариант для колледжа.

Рабочие варианты без VPN (проверка Хабра, 21.10.2026):

| Сервис | Бесплатно | Модели | Замечания |
|---|---|---|---|
| GigaChat API (Сбер) | фритир для физлиц; по обзорам ~365 млн токенов/год на Lite | GigaChat Lite и др. | РФ-сервис, Sber ID; модулю нужен маленький адаптер (OAuth) |
| Token Harbor | $0, квота на 7 дней циклом, 60 запр/мин | DeepSeek V4.1 Flash, MiMo V2.6 Flash | англ. интерфейс, рубли не нужны (бесплатно) |
| TeamoRouter | «по акции» ~0,000001$/запрос — фактически бесплатно | DeepSeek V4.1/V4 Flash, GLM 5.3 Flash | RU, рубли, русский интерфейс |
| Srazu | 5 запросов/день суммарно | DeepSeek, Llama 3.3 70B, GPT-OSS и др. | мало для класса, рубли |
| llmgw | платный, но копеечный (GPT-4o-mini ~$0.000003/запрос), бонус 0,10 ₽ | OpenAI и др. | RU, рубли — запасной |
| Ollama Cloud | фритир с часовыми/суточными лимитами | открытые модели | тот же API, что локально; доступность из РФ проверить |

Платные из РФ без VPN: ProxyAPI, GetAPI (OpenAI/Claude/Gemini/DeepSeek/
Qwen, рубли, списание по факту) — как недорогой запасной канал.

Вывод: **локальная модель — база** (занятие не зависит от интернета,
лимитов и согласований); внешний API — опциональный «быстрый/глубокий»
режим или фолбэк. Лимиты у всех меняются без анонсов — перед выкаткой
перепроверить руками; у мелких реселлеров проверять подмену модели
(по `usage` и совпадению ответов разных моделей).
Приватность: наружу не отправлять ФИО и служебную документацию
(у источников модуля — флаг «можно наружу»).

## 7. Баг-репорт #1 «Нейросеть не отвечает» — РЕШЁН (13.11.2026)

Студент (s3, 10:05:12): «Ответы не возвращаются. Пишется ошибка» — шторка
показывала «Ошибка подсказок» на каждый вопрос, при этом журнал модуля
фиксировал УСПЕШНЫЕ ответы (09:50–10:02, сек 13–36, провайдер «локально»).

Корень: **несовпадение имени поля в JS шторки** — ответ читался как
`j.ok` (латиница), а сервер шлёт `{"ок": true}` (кириллица). `j.ok`
всегда undefined → ветка else → `j.ошибка` отсутствует → фолбэк
«Ошибка подсказок». Сервер считал ответ честно (в журнале он есть),
студент его ни разу не увидел. Регресс-тест не ловил: проверял JSON
сервера (`j.get("ок")`), а не JS браузера.

Исправлено в modules/podskazki/модуль.py:
1. `_FRAG`: `if(j.ok)` → `if(j.ок)`; в тест добавлена проверка имени поля.
2. Шторка переживает не-JSON ответ сервера (500/404 html): раньше
   `r.json()` падал в catch с вводящим в заблуждение «Нет связи с
   сервером подсказок» — теперь честный «Сервер СДО вернул ошибку (HTTP …)».
3. `ask()` — внешний catch-all: любая непредвиденная ошибка до fin()
   (раньше — 500 `{"error": …}` без записи в журнал) теперь отдаёт
   студенту понятную JSON-ошибку И пишется в журнал.
4. Журналирование любой ценой: `_log` не роняет ответ при сбое записи,
   `kv_save` с повторами (Windows transient-блокировки файла), чтение
   лимита — под замком.
5. Защита от битых файлов хранилища: журнал/кэш/настройки с неожиданным
   типом (kv_load возвращает `{}` при нечитаемом файле) больше не рушат
   запрос — журнал восстанавливается как список, битая запись кэша
   пропускается, битый индекс → честная ошибка.
6. `_embed` не падает IndexError при пустом ответе эмбеддера.

Тест: tests/_chk_podsk.py — 39 проверок (было 32), все зелёные; деплой
на боевой — автоматически через конвейер CI (стенд :8090 → боевой
/_reload, горячая перезагрузка без рестарта сервера).

Попутно выяснено при отладке:
- «молчаливый незагруз модуля» на отладочном :8093 был фантомом: порт
  держал зомби-процесс от 11.11 (--store _sc_dbg); модуль грузится
  нормально (проверено прямой загрузкой без HTTP: 20/20 модулей ok).
- Наблюдатель CI частично виснет на `localhost:8080` (::1 первым в
  getaddrinfo) — фактические опросы проходят через IPv4-фолбэк;
  для надёжности стоит перейти на 127.0.0.1 (v2).


## 8. Кликабельные источники с подсветкой фрагмента (13.11.2026)

- Ответ нейросети теперь несёт «фрагменты»: на каждый файл-источник —
  самый релевантный чанк и его хэш (sha1 текста [:8]); фрагменты едут
  и из кэша.
- Чипы «📄 файл» в шторке стали ссылками: открывается страница
  «/podskazki/просмотр/<файл>/<хэш>» (доступ any) — документация
  показывается по фрагментам, использованный подсвечен жёлтым
  (анимация-вспышка) и проскроллен в центр.
- Если хэш не найден (индекс пересобран) или не передан — страница
  показывает весь документ без подсветки; если чанков нет вовсе
  (индекс пуст) — текст извлекается из файла на лету (_extract).
- В истории панели /podskazki источники тоже кликабельны.
- Выход за папку источников запрещён (basename + isfile).
- Тест: +5 проверок (44 всего) — фрагменты в ответе и в кэше, просмотр
  с подсветкой и без, запрет traversal.


## 9. «Кнопка не работает» — сломанный JS правкой (13.11.2026)

После выкатки кликабельных источников кнопка «🤖 Подсказка» перестала
открывать шторку: правка хвоста вызова `add(...)` вставила новый аргумент
`,j.фрагменты` ПОСЛЕ закрывающей скобки вызова — лишняя `)` дала
SyntaxError, весь скрипт шторки падал, обработчики не вешались.
Найдено прогоном `node --check` по скриптам реальной страницы.

Исправление + защита от повторения:
- вызов поправлен: `...+" с":""),j.фрагменты)}` →
  `...+" с":""),j.фрагменты)}` с аргументом ВНУТРИ вызова;
- в tests/_chk_podsk.py добавлена проверка скрипта шторки со страницы:
  баланс скобок (учёт строк), фрагменты внутри вызова `add(...)`,
  и при наличии node — полный `node --check` (пропускается, если node
  нет). Теперь сломанный JS ловится тестом до деплоя.

Урок: правки _FRAG проверять не только py_compile (он не видит JS),
но и разбором JS — в тесте это теперь навсегда.


## 10. Массовая загрузка документации (13.11.2026)

  целый комплект документации (подпапки разворачиваются в корень,
  служебные файлы __MACOSX/Thumbs.db/desktop.ini пропускаются);
- русские имена в архивах: современный utf-8 (флаг), Проводник Windows
  (cp866), старые архиваторы — эвристика cp1251 (если в cp866-варианте
  появились псевдографика U+2500–U+25FF); возможны кривые имена только
  у редких cp1251-архивов — содержимое при этом корректно;
- лимиты: архив ≤ 100 МБ, ≤ 300 файлов, ≤ 300 МБ распаковки, файл ≤
  20 МБ (как и раньше), расширения — только txt/md/markdown/log/docx/pdf;
- после каждой загрузки пишется отчёт «загрузка.json» и показывается
  на панели: что сохранено и что пропущено с причинами (формат, размер,
  служебный файл, непрочитанный архив);
- после массовой загрузки не забывать «🔄 Пересобрать индекс»
  (прогресс-бар уже есть).

Тест: +6 проверок (итого 55) — zip с вложенными папками, cp866-имя,
отсев .exe, отчёт в загрузка.json и на панели.


## 11. Догрузка «⚡ Только новое» — инкрементальный индекс (13.11.2026)

Это реально: индексировать всё заново не нужно. Эмбеддинги — чистая
функция текста чанка, поэтому неизменённые файлы переиспользуются
с готовыми векторами.

- индекс.json хранит «файлы»: {имя: mtime}; «⚡ Только новое»
  (POST /podskazki/догрузить) сравнивает mtime и эмбеддит только
  новые/изменённые файлы; удалённые файлы выпадают из индекса;
- «🔄 Пересобрать индекс» остался полным (смене эмбеддера/промта
  чанкера и т.п.);
- кэш ответов при догрузке не сбрасывается целиком: вычищаются только
  ответы, ссылающиеся на изменённые файлы (полная пересборка, как и
  раньше, чистит весь кэш);
- если новых файлов нет — ничего не пересчитывается и не трогается,
  панель показывает «обновлено 0 — нет, без изменений N»;
- хэши фрагментов неизменённых файлов стабильны → ссылки-подсветки
  в старых ответах продолжают работать;
- первый догрузку после этого обновления модуль сделает полной
  (в старом индексе ещё нет mtime-карты) — дальше быстро.

Тест: +9 проверок (итого 64) — состав обновлённых, переиспользование,
поиск по новому документу, стабильность хэшей, повторная догрузка,
итог на панели.


## 12. Таблицы и картинки в документации (13.11.2026)

Проблема: извлечение текста теряло структуру — docx срезал все теги
(таблицы сплющивались, картинки пропадали), pdf по умолчанию ломал
колонки.

Сделано (извлечение v2, «ИЗВ_ВЕРСИЯ» в индексе):
- **docx таблицы** → строки вида «Параметр | Значение | 60 мкА»
  (разбор w:tbl/w:tr/w:tc, вложенные таблицы разворачиваются изнутри);
- **docx картинки** → файлы из word/media распаковываются в
  данные/модули/podskazki/источники_медиа/<док>/, в тексте на их месте
  остаётся маркер «[Рисунок N: image1.png]» — модель видит, что тут был
  рисунок, студент в просмотрщике видит сам рисунок;
- **pdf** → extract_text(extraction_mode="layout") (колонки/таблицы
  держат выравнивание; старый pypdf — откат на обычный режим),
  каждая страница помечена «[Страница N] [Рисунков: K]» — модель может
  ссылаться на страницы;
- **просмотрщик** рендерит маркеры: [Рисунок N: файл] → <img> с
  /podskazki/медиа/<док>/<файл> (только изображения по расширению,
  выход за папку запрещён), [Страница N] → бейдж «— стр. N —»;
- удаление источника чистит и его медиа-папку;
- важно: «⚡ Только новое» после этого обновления само сделает полную
  переобработку один раз (индекс ещё без «извлечение: 2») — нажать
  один раз, дальше снова быстро.

Баг по пути: у регэкспа blip не было группы захвата, а обработчик читал
m.group(1) — все docx падали в «не прочитан»; поймано тестом.

Тест: +5 проверок (итого 69) — собранный кодом docx с таблицей и
картинкой: таблица в тексте чанка, <img> в просмотрщике, выдача
картинки по /podskazki/медиа/, поиск по содержимому таблицы.
